# Bug pipeline: v2 -> v2-corrected -> v3

Этот файл — рабочий чеклист, чтобы найденные расхождения не терялись между сессиями.
Он не является текстом диплома. Формулировки для LaTeX будут отдельно, без разбора
бакалаврской работы.

## Правила

- Источник истины по смыслу — текст диплома. Если текст и код расходятся, сначала
  решаем, это опечатка в тексте или ошибка в коде, и фиксируем решение здесь.
- `x10` — внутреннее целочисленное представление. На границах делим на 10.
  В текст это не тащим.
- Детерминизм прогона обеспечивается seed-потоками и стабильным порядком обхода,
  а не «детерминированным порогом».
- v2.0.0 — исторический оригинал, не переписываем.
- v2-fixed — исправленная версия старого ядра. Все результаты для сравнения
  генерируются заново.
- v3-master-coursework — чистая реализация на Rust. Сюда не тащим старую
  архитектуру, только проверенную семантику.

## P0. Блокеры v2-corrected

### 1. OpenMP race в `Engine::influence_emotions`

- Где: `core/src/engine.cpp:7-80`.
- Что: `delta_emotions[offset_j + a] += delta` пишут разные потоки в один элемент.
- Следствие: сумма эмоций и финальное состояние зависят от `OMP_NUM_THREADS`.
- План: инвертировать циклы — параллелиться по `j` (цель влияния), внутри `j`
  идти по `i` в фиксированном порядке и аккумулировать в локальный `float[7]`.
  Предварительно посчитать primary axis / weights для каждого `i`.
- Проверка: N=100/400, seed фиксирован, 1/2/8 потоков -> одинаковый хэш эмоций
  и отношений.

### 2. C++ RNG: `rand()` -> детерминированный поток

- Где: `core/src/engine.cpp:126`, `:173`, `:399`.
- Что: платформенный `rand()`; состояние общее, последовательность зависит от
  платформы/порядка вызовов.
- План: `std::mt19937` в `Engine`, `seed(int)` задаёт состояние. Использовать
  собственные преобразования (`rng() % 100`, `rng() >> 8`), а не
  `uniform_real_distribution`, чтобы не зависеть от реализации STL.
- Проверка: два запуска с одним seed -> одинаковый хэш; 1/2/8 потоков -> одинаково.

### 3. Sigma: строки, bool и `type_map`

- Где:
  - `model/university_collective.py:665` передаёт `"success"`/`"failure"`;
  - `core/interaction_strategy.py:170-182` сравнивает с `1`/`-1`;
  - `model/collective.py:481` передаёт bool в C++;
  - `model/collective.py:521` мапит `2 -> "fail"`, а C++ пишет `-1`.
- Что: `process_interaction_result` не видит ни успех, ни неудачу; bool `False`
  превращается в sigma `0`; fail логируется как refusal.
- План: ввести `Outcome { SUCCESS=1, REFUSAL=0, FAILURE=-1 }`.
  Python API принимает `Outcome` или int и нормализует. C++ API принимает int
  `-1/0/1`. `type_map = {-1: "fail", 0: "refusal", 1: "success"}`.
- Проверка: success -> положительные дельты; failure -> отрицательные;
  refusal -> отрицательные у обоих; лог совпадает с фактическим исходом.

### 4. Отказ: цель, оба участника, все три функции, контекст

- Где:
  - `core/interaction_strategy.py:128-154` — штраф только инициатору, только одна ось;
  - `core/interaction_strategy.py:11-16` — только базовый шанс, без отношений;
  - `core/src/engine.cpp:230-244` — то же в C++;
  - `model/university_collective.py:654` — уже цель, но без отношений/контекста;
  - `model/collective.py:432` — инициатор вместо цели.
- Текст: `pdf/Таджиев Георгий.tex:158`, `:324`, `:357` — при отказе оба участника
  корректируют все три функции строго отрицательно, величина зависит от архетипа.
- План:
  - `Archetype.refusal_impact = {utility, affinity, trust}`;
    по умолчанию главная ось из `refusal_vulnerability` = 1.0, остальные = 0.5.
  - `calculate_refusal_chance(target, initiator, context)`:
    базовый шанс цели, множитель от отношений цели к инициатору и контекста.
    Нейтральные отношения -> базовый шанс; плохие -> выше; хорошие -> ниже.
    Clamp `[0.01, 0.95]`.
  - `process_refusal(initiator, target, context)`:
    для обоих участников `U/A/T -= 20 * sensitivity * impact * context_factor`.
  - C++: та же семантика; `refusal_vulnerability` остаётся только для выбора
    главной оси, не для veto.
- Проверка: отказ ухудшает 6 направленных отношений (3 у инициатора, 3 у цели);
  вероятность отказа растёт при плохих отношениях цели к инициатору.

### 8. C++ relation updates теряются в university mode

- Где: `model/university_collective.py:230-236` — `_sync_from_cpp(sync_relations=False)`.

  Python-взаимодействия перезаписывают C++ значения через `RelationDict`.
- План: синхронизировать отношения в обе стороны после C++-шага
  (`_sync_from_cpp(sync_relations=True)`), либо явно отключить relation-обновления
  в C++ и делать их в Python. Для v2-corrected выбираем sync, чтобы не менять
  алгоритм.
- Проверка: после слота значения `agent.relations` отражают C++ decay/react;
  суммарный баланс отношений не «застревает».

## v3. Что должно быть в новой архитектуре

- `Outcome { Success, Failure, Refusal }`, `Context`, `RefusalImpact`.
- `BehaviorModel` (Archetype / Trait OCEAN/HEXACO) и `World`
  (University / Apartment) — ортогональные оси.
- `World × BehaviorModel` = 4 условия: 2 мира × 2 модели. OCEAN vs HEXACO

- Агенты — `Vec`, отношения — плоский `Vec` по `AgentId`; никаких `HashMap`
  в обходе.
- RNG — `ChaCha12`/`mt19937` с иерархическими seed-потоками; фиксированный
  порядок редукций.
- Параллелизм — по независимым индексам, без общих записей.
- Тесты: 1/2/8 потоков -> одинаковый хэш; refusal; sigma; сбросы; группы 10/12;
  три секции GYM; ротация.
- WebUI: viewer (карта, инспектор, шаги, графики), затем live.
- ClickHouse: metadata + checkpoints/deltas, без полной матрицы каждый день.

## Решения, принятые при аудите

### Отказ

- Отказ определяет цель, а не инициатор. Вероятность зависит от отношений
  цели к инициатору и от контекста.
- При отказе оба участника ухудшают все три функции друг к другу. Главная
  ось архетипа (`refusal_vulnerability`) получает полный вес, остальные —
  половинный. Это соответствует тексту и не является «вето» на выбор цели.
- `Outcome { FAILURE=-1, REFUSAL=0, SUCCESS=1 }`; C++ и ClickHouse хранят
  `-1/0/1`, bool и строки нормализуются на границе Python.
- Пустой список целей — это отсутствие контакта, а не отказ. Штрафовать
  всех агентов за отсутствие цели нельзя.

### Контекст

- В университетском режиме контекст передаётся во все парные взаимодействия:
  аудитория — `STUDY`, коридор — `BREAK`, спортзал — `GYM`.
- В общем (не университетском) режиме пространственного контекста нет;
  это осознанная граница v2, а не забытый аргумент. В v3 контекст будет
  обязательным свойством мира.

### Магистратура

- 6 направлений × 2 года = 12 когорт по 10 человек, всего 120.
- Когорта набора `ММ-24` остаётся `ММ-24` и на M1, и на M2; меняется только
  `course_year`. Это позволяет не терять расписание и социальные связи.
- 30% бакалавров получают шанс продолжить обучение, но в когорту набора
  попадает не больше 10 человек. Остальные места занимают внешние
  магистранты. Так одновременно выполняются оба требования текста:
  «30% продолжают» и «до 10 человек в группе».
- Выпуск: бакалавры — через 4 года, магистры — через 2 года от года набора.

### Спортзал

- Секция выбирается равномерно при входе в зал (`SportType`), а не по
  терцилю спортивности.
- `sportiness` влияет только на посещение зала; `status != HOME` — это
  предварительное условие (агент уже ушёл домой).
- Три секции — изолированные графы: контакты между секциями внутри зала
  запрещены, даже на границе секций.

### Эмоции и отношения

- Затухание эмоций и отношений, реакция на отношения и эмоции выполняются
  один раз в день, в конце дня (`CLEANUP`), как в общем цикле симуляции.
  Повтор после каждой пары превращал `d_E=0,2` в девятикратное затухание
  за день и гасил эмоции к концу первого учебного дня.
- В университетском режиме теперь вызывается и `apply_relation_decay`;
  раньше отношения в этом режиме вообще не затухали.
- Эмоциональное влияние — это шаг к взвешенному среднему ближайшего круга
  (top-K по силе связи), а не сумма «эмоция партнёра × связь» по всем
  знакомым. Сумма по всем `N` давала неограниченный рост и насыщение ±30;
  шаг к среднему ограничен и сохраняет различия между группами.
- Исход контакта `sigma` одинаково используется и для отношений, и для
  эмоций. Для `U/T/A` успех и неудача повышают значения (неудача — с
  половинной дельтой), а отказ — единственный исход, который их понижает.
  Для эмоций успех и неудача сближают профили с партнёром (неудача — с
  половинной дельтой), а отказ — единственный исход, который разводит.
  Это соответствует тексту: эмоция зависит от `sigma` и `E_j`, а отказ
  является разрывом контакта.
- Внутренний масштаб `x10` сохраняется; на границах (CSV/ClickHouse/UI)
  значения уже целые в диапазонах `[-30, 30]` и `[-100, 100]`.

### Воскресенье

- Каждый агент получает своё случайное `delta in [-30, 30]`, но одно и то
  же для всех семи осей своего вектора. После сдвига применяется обычное
  затухание. Общий `delta` на весь коллектив не соответствует тексту.

### Классификация отношений

- `classify_relationship` и `categorize_relationships` остаются только как
  постфактум-разметка для графиков. В выборе цели, отказе и рассадке они
  не участвуют. Пороговые категории не являются частью модели поведения.
